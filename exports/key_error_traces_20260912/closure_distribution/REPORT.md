# 基础模型：学生闭合 reasoning 时的教师分布审计

**结论：存在局部格式监督冲突，集中在开始闭合的`</` token；不是普遍不认可闭合标签。** BF16、T=0.6下，412个位置的学生平均闭合概率99.997998%，教师99.162209%；2处其他候选`<`超过`</`，另1处并列；10处教师概率比学生低超过5个百分点。后续`reason`、`ing`、`>\n\n`片段在全部位置都保持最高概率。

模型为原始Qwen3-4B（我们OPD训练前的step0），不是step20。使用此前随机抽取的10道ALFWorld训练题、不带hint的学生轨迹。414个turn中412个含有闭合标签，检查这些turn的全部闭合片段；另2个达到1024-token上限且没有闭合标签，列在excluded.json。

学生与教师使用同一份原始模型权重和完全相同的学生response prefix。教师仅在原始prompt的既定位置添加L1；GLM只根据任务、当前观察、最近2次动作提供hint，不看到学生当前响应或oracle。已有相同公开状态的hint直接复用，另226个状态按原配置生成，GLM-5.3-flash thinking=true、effort=low、max_tokens=768、并发128。

每个位置统计softmax(logits / temperature)的完整词表分布：同时报告T=1.0与训练温度T=0.6，不做top-k/top-p截断。Top-20只用于展示候选和复现训练损失，候选概率没有重新归一化。所有熵均以自然对数计算，单位nats。

梯度来自当前仓库compute_topk_forward_kl_with_tail对目标token缩放后logit的导数，尚未做全batch平均。正值表示在独立logit坐标下梯度下降会压低该logit，负值会提高；共享模型参数的一次实际更新还会受其他token和样本影响。这不是对训练崩坏的因果证明。8个worker均用自动微分核对了梯度解析式。

闭合起始位置的KL也集中于少数样本：损失最高的10个位置占全部412个闭合起始位置KL之和的89.60%。因此高平均闭合概率不代表所有闭合位置都没有负向监督。该比例仅针对首个闭合token，不能解释成全训练loss占比。

## 短续写核对：确实有教师直接进入action的反例

对教师闭合概率最低的10个学生prefix，分别用带hint/不带hint条件做最多20-token的greedy续写，不执行环境动作。学生10/10从`</reasoning>`开始；教师9/10正常闭合，题6 Turn1直接开始`<action>`。完整记录见[branch_continuations.jsonl](branch_continuations.jsonl)。

**题6 Turn1 / student 在同一个学生prefix后的实际续写**

```text
</reasoning>

<action>go to cabinet 1</action><|im_end|>
```

**题6 Turn1 / teacher 在同一个学生prefix后的实际续写**

```text
<action>
go to cabinet 1<|im_end|>
```

BF16下计算批大小和序列长度改变会导致边界候选排序变化：例如题2 Turn1在整段teacher-forcing打分中`<`为Top1，但批量短续写时`</`为Top1。因此补做以下FP32数值核对，不能把两种计算的具体概率混为一份测量。

## FP32复核：原始权重不变，SDPA数学注意力，关闭TF32

| 题号/Turn | 学生P(`</`) T=0.6 | 教师P(`</`) T=0.6 | 教师P(`<`) T=0.6 | 教师在`<`后最高概率token |
|---|---:|---:|---:|---|
| 2/1 | 99.805814% | 37.403390% | 62.596607% | `action` 99.999952% |
| 6/1 | 99.992108% | 16.844405% | 83.155590% | `action` 60.486031% |
| 9/1 | 99.894553% | 62.595630% | 37.404370% | `action` 99.999976% |

FP32再次确认题2和题6 Turn1更偏好`<`而非`</`；题9偏好正常闭合。题2在`<`后几乎确定接`action`；题6在`action`与`reason`间有分歧，最高概率仍为`action`。同一教师prefix的完整teacher-forcing与截断prefix计算，在这3例FP32核对中的最大logit差异均为0，排除了读取位置错位和可见未来token造成此现象的解释。

这确认了基础模型上的局部错误监督信号；尚不能证明它是训练后大规模格式崩坏的主因，也不能把10题的turn级比例推广到全训练集。

## 边界与验证

- 主统计的闭合位置指学生实际输出闭合标签时的prefix；这是条件分布检查，后续短续写单独记录。
- 首个片段通常是`</`，它本身不等于整个`</reasoning>`的概率；后续片段分别在已接上学生前面片段的条件下评分。
- 表中100%是浮点数计算或显示精度结果，不表示数学意义上其他候选严格为零。
- 其他token概率更高可能意味着继续推理、增加换行或改写，并不自动意味着会遗漏闭合标签；短续写用于进一步核对具体候选含义。
- 闭合前3个位置与每turn均匀选取的8个正文位置作为参考，不能代替对全部正文token的统计。
- 主统计使用BF16、FlashAttention2和原始模型。8个worker均通过相同输入下原生causal-LM forward与选择性logits读取的严格一致性检查；另外记录不同prefix长度的BF16数值差异。未修改训练代码，未做权重更新。
